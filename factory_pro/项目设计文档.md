## 1. 项目概述

FactoryGuard 是一套基于真实硬件的智慧工厂安全监测控制平台，实现：

- **实时监测**：温湿度、可燃气体、烟雾、光照、人员在场等环境数据采集与可视化
- **远程控制**：继电器输出、RGB 指示灯、蜂鸣器、Flash 库存的 Web/小程序/3D 孪生场景下发
- **智能告警**：气体/温度超标自动告警，并联动硬件（红灯 + 蜂鸣）
- **智能联动**：用户自定义 Trigger-Action 规则引擎 + 一键场景模式
- **数据治理**：历史数据存储、7 天自动清理、CSV 报表导出
- **AI 安全帽检测**：图片上传 / 本机摄像头 / RK3568 USB 摄像头实时视频流（MQTT 推帧 → 4 秒节流自动推理 + 帧龄保护），YOLOv8 后端经推理微服务调用
- **AI 助手「小鸿」**：DeepSeek 驱动，双端可用（Web 悬浮 Widget 流式对话 / 小程序对话页），上下文注入真实传感器数据、巡检与反馈概况、双端功能导览
- **多工厂管理**：工厂 → 车间 → 设备三级层级，web/小程序双端增删改查与切换过滤
- **意见反馈**：分类/严重度/截图反馈，状态流转 + 官方回复闭环，QQ 邮箱异步通知
- **3D 数字孪生**：多工厂场景（真实工厂 + 演示厂区）、真实执行器 3D 直控、真实告警 3D 联动
- **双端架构**：Web 端（Vue 3 管理控制台，16 个内容页）+ 支付宝小程序端（Taro 4，17 个页面）

数据链路全程真实：STM32 传感器 → RK3568 网关 / 摄像头程序 → MQTT → 后端 → WebSocket / MJPEG → 前端页面。

## 3. 硬件协议（v1.0 摘要）

### 3.1 连接参数


| 项              | 值                                                                        |
| ----------------- | --------------------------------------------------------------------------- |
| Broker          | `192.168.1.100:1883`（文档约定；本地测试按实际电脑 IP 调整）              |
| MQTT 版本       | 3.1.1（Level=4），匿名，Keep Alive 60s，Clean Session true                |
| 传感器 ClientID | `rk3568_factory_001`（**全网唯一，与模拟器互斥**）                        |
| 摄像头 ClientID | `rk3568_camera_001`（rk_camera.c 独立程序，与传感器网关不同，可同时在线） |

### 3.2 上行：`factory/sensor/data`（QoS 0，2 秒一帧）

扁平 JSON，字段与硬件一一对应：


| 字段                  | 类型   | 说明                                                    |
| ----------------------- | -------- | --------------------------------------------------------- |
| ts                    | int64  | Unix 秒时间戳（0 = 硬件时钟未同步，后端回退服务器时间） |
| temp / humi           | float  | 温度 ℃ / 湿度 %（DHT11）                               |
| mq5_ppm / mq2_ppm     | uint16 | 可燃气 / 烟雾浓度 ppm                                   |
| mq5_level / mq2_level | uint8  | 归一等级 0~100                                          |
| ldr_adc               | uint16 | 光敏 ADC 0~4095（光弱值大）                             |
| pir                   | uint8  | 人体红外 0/1                                            |
| light_on              | uint8  | 继电器灯状态 0/1                                        |
| rgb_color             | uint8  | RGB 颜色 0~7（0关 1红 2绿 3黄 4蓝 5品红 6青 7白）       |
| beep                  | uint8  | 蜂鸣器 0/1                                              |
| count / stock         | uint16 | RAM 计数 / Flash 持久化库存（每 100 次落盘）            |

摄像头通道：`fg/{device_id}/camera`（**裸 JPEG 二进制帧**，QoS 0，约 3 秒一帧）——由 RK3568 上的 `rk_camera.c` 独立程序推流（V4L2 抓拍，零第三方依赖，STM32 侧零改动）。后端每帧沉淀为 `data/images/stream/latest.jpg` 供 web/小程序拉取与 MJPEG 直播，并按 4 秒节流触发自动推理（检测记录 camera 标记 `rk3568_usb`）。

另有 HTTP 调试通道：`POST /api/stream/frame`（raw JPEG 或 multipart 字段 `file`）——**只进视频流缓存、不触发自动推理**，用于 rk_camera 联调与桌面工具推帧。

### 3.3 下行：`factory/device/cmd`（QoS 0）

```json
{ "method": "<命令名>", "params": { ... } }
```


| method      | params                           | 说明                                          |
| ------------- | ---------------------------------- | ----------------------------------------------- |
| relay       | `{"val":0                        | 1}`                                           |
| rgb         | `{"val":0~7}`                    | RGB 颜色（0关 1红 2绿 3黄 4蓝 5品红 6青 7白） |
| beep        | `{"on_ms":0~255,"off_ms":0~255}` | 蜂鸣节奏（双 0 = 静音）                       |
| stock       | `{"val":0~65535}`                | 改写 Flash 库存（整页擦写，寿命约 1 万次）    |
| stock_reset | （无参数）                       | 清零库存                                      |

### 3.4 业务逻辑约定

- 气体报警：`mq5_ppm > 900` 或 `mq2_ppm > 300` → 硬件红灯 + 蜂鸣
- 照明逻辑：`pir == 1 且 ldr_adc > 2000` → 自动开灯
- 库存差值：`count - stock` 为未落盘增量（<100）

### 4.3 核心数据流

**传感器上行**（每 2 秒一帧）：

```
factory/sensor/data → Paho 回调（只做转发，严禁在回调线程 publish——Paho 死锁坑）
  → mqttWorker 单线程池 → 解析扁平 JSON（ts=0 回退服务器时间）
  → sensor_readings 入库 → device_status upsert（90 秒无数据扫描置离线）
  → WebSocket broadcast("sensors")
  → AlertEngineService（状态翻转去抖，超标→落库告警+联动红灯/蜂鸣，恢复→自动解除）
  → RuleEngineService.evaluate（用户自定义规则，同款去抖）
```

**摄像头帧上行**（`fg/{deviceId}/camera` 裸 JPEG，rk_camera.c 约 3 秒一帧）：

```
Paho payload 原始字节（严禁经 String(UTF-8) 往返——JPEG 会损坏，实际踩坑修复过）
  → 从 topic 解析真实设备号（替代固定 defaultDeviceId）
  → StreamFrameService.updateFrame：JPEG 魔数（FF D8）校验，非法帧丢弃并记 warn
    → 内存缓存 + 原子落盘 latest.jpg（重启恢复取文件 mtime，防止磁盘残留旧图被当实时帧）
  → 距上次推理 ≥4 秒才触发自动 YOLO 推理（节流防高频打爆 CPU；
    HTTP 调用 10 秒超时 + 响应结构校验，防推理服务假死冻结队列）
  → 检测结果入库（camera=rk3568_usb）+ WebSocket 推送 + 未戴帽告警
```

**实时视频流与帧龄保护**（v3.1 新增，配合硬件联调）：

```
Web 检测页：<img> 直连 GET /api/stream/live（MJPEG multipart/x-mixed-replace，
            120ms 轮询去重推送，10 分钟兜底断开）；失败自动回退每秒轮询 /api/stream/latest
web/小程序定时检测：轮询 GET /api/stream/info 读 frameAgeSeconds
  → >15 秒判定「帧已停更」：画面标注非实时 + 自动停止送检（防止旧帧污染 detections 表）
  → 帧恢复新鲜后自动重置；framesReceived 字段可验证推帧持续（10 秒 +3 左右为正常）
```

**小程序检测请求**：

```
Taro.uploadFile(multipart image) → POST /api/detections/detect
  → DetectionService：原图落盘 raw/ → HTTP 调 8001 推理（15s 超时）
  → 标注图（base64）落盘 boxed/ + 随响应返回 → detections 入库 → no_helmet 告警
  → 小程序直接显示 base64 标注图（绿框合规/红框未戴 + 置信度）
```

**反馈提交**：

```
POST /api/feedbacks（登录即可，双端身份自动识别）→ feedbacks 入库
  → MailService 异步线程：QQ SMTP 465 SSL 发通知邮件（未配置授权码自动跳过，失败仅记日志）
  → admin 在双端处理（状态流转 + 回复）→ 提交者列表可见回复（闭环）
```

**下行控制**（`publishCommand`）：

```
REST 请求 → 校验（协议白名单 + uint8 钳制）→ factory/device/cmd 发布 QoS 0
  → command_logs 落库（source: manual/auto/scenario）→ request_id 返回前端
```

### 4.4 关键设计决策


| 决策                                             | 理由                                                                                                                                       |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| MQTT 回调线程只转发、业务入独立单线程池          | Paho v3 在回调线程内同步 publish 会死锁（实际踩坑修复过）                                                                                  |
| **camera 帧保留原始 byte[]，不做 String 往返**   | UTF-8 解码会把 JPEG 无效字节替换为 U+FFFD（86KB 帧膨胀至 165KB 且无法解码，实际踩坑修复过）                                                |
| **重启恢复帧取文件 mtime 而非当前时间**          | 曾把磁盘残留旧测试图当实时帧，造成「检测到旧图」假象（9/5 实际踩坑修复）                                                                   |
| **JPEG 魔数（FF D8）校验，非法帧丢弃**           | 拦截损坏/伪造帧污染视频流缓存                                                                                                              |
| **HTTP 推帧（/api/stream/frame）不触发自动推理** | 调试通道只进缓存，避免联调推帧打爆推理服务                                                                                                 |
| **YOLO HTTP 调用 10 秒超时 + 响应结构校验**      | 推理服务假死会冻结单线程 cameraQueue（队列同时承担 updateFrame）（9/5 修复）                                                               |
| **帧龄保护（>15 秒停送检）**                     | 硬件停更后继续拿 latest 帧送检会产生重复脏数据（9/5 联调结论）                                                                             |
| 重连后主动重新订阅（MqttCallbackExtended）       | Paho automaticReconnect + cleanSession=true 不恢复订阅                                                                                     |
| 告警/规则均用「状态翻转」触发                    | 上报周期 2 秒，连续帧去抖，避免告警刷屏与执行器高频动作                                                                                    |
| **推理独立微服务（Python :8001）+ 4 秒节流**     | PyTorch 环境与 Java 解耦，可独立部署边缘端；节流防高频帧打爆 CPU                                                                           |
| **双端身份双键兼容**（openid / username）        | 小程序与 web 共用一套 admin 校验，两种 token 均可识别                                                                                      |
| **字段双格式兼容策略**                           | DeviceController/HazardController 历史上输出 snake_case，小程序 API 层做`row.deviceId || row.device_id` 兼容，后端不动（web 端依赖原格式） |
| **写操作失败真实抛错**                           | 上报/处理/控制/通知设置曾经 catch 后伪装成功误导用户（实际踩坑修复过）                                                                     |
| 实体类 snake_case 字段加 @JsonProperty           | Jackson 默认不认`action_method` 等 key，否则静默变 null（实际踩坑修复过）                                                                  |
| 下行命令白名单 + 参数钳制                        | 防注入；uint8 协议上限（beep ≤255 等）                                                                                                    |
